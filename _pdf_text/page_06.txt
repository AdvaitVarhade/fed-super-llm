1) BLUEPRINT-BASED MERGING: INTUITION AND EXAMPLE
Algorithm 2 constructs the final recommendation list using a
hard quota / soft blueprint strategy. First, the user-specific
popularity inclination Popu determines a hard head–tail
composition for the final top-N list via Npop = ⌊N· Popu⌋
and Ntail = N − Npop. This quota is enforced strictly: even
if the user’s historical list Lu is dominated by head items at
the top ranks, once the head quota is satisfied, the remaining
positions must be filled from the tail pool (and vice versa).
Given these hard quotas, the blueprint derived from Lu is
used only as a soft, rank-level ordering prior that decides
which pool to draw from next as long as the corresponding
quota is still available. Concretely, the algorithm first
truncates the two candidate pools to Cpop and Ctail containing
the top- Npop and top-N tail items from the popular-only and
tail-only models, respectively. It then scans the first B =
min(N, |Lu|) positions of Lu to obtain a head/tail indicator
at each rank, and attempts to follow this indicator when
selecting the next item. If the blueprint requests a pool whose
quota is already exhausted, the method deterministically falls
back to the other pool, thereby maintaining a valid top-N list
while preserving the hard head–tail composition dictated by
Popu.
From a conceptual perspective, this blueprint acts as a
lightweight positional regularizer : proportional allocation
alone controls the aggregate head–tail ratio but does not
constrain where exposure occurs across ranks, which may
lead to position-level miscalibration. By introducing rank-
aware guidance without altering backbone relevance scores,
the soft blueprint stabilizes exposure distribution across
positions, while the hard quota guarantees that the final list
always matches the user-specific popularity inclination. For
short or noisy histories, we apply the blueprint only for the
first min(N , |Lu|) ranks and fill any remaining slots using the
residual user-specific quotas. If the blueprint covers fewer
than N positions (i.e., |Lu| < N), the remaining ranks
are filled greedily from the residual pools while strictly
satisfying the hard quotas (N pop, Ntail); in this completion
phase, the exact within-quota ordering is not constrained by
the blueprint.
2) WORKED EXAMPLE
Consider a target list size N = 6 and a user with Popu = 0.5,
yielding Npop = 3 and Ntail = 3. Assume the user’s real
rating list Lu induces the following head–tail blueprint over
ranks:
Lu = [Pop, Tail,Pop, Pop, Tail,Tail].
Let the quota-limited candidate pools (sorted by predicted
relevance within each pool) be
Cpop(u) = [p1, p2, p3], Ctail(u) = [t1, t2, t3].
The list is then constructed under a hard quota / soft blueprint
rule: at each rank, the blueprint requests either head or tail,
but the algorithm selects from that pool only if its remaining
quota allows; otherwise it deterministically switches to the
other pool. For the above blueprint, all requests are feasible
within the quotas, hence scanning Lu yields
RecList(u) = [p1, t1, p2, p3, t2, t3].
