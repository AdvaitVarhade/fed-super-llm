C. ESTIMATING USER POPULARITY INCLINATION
A key insight of our approach is that not all users value
popularity equally. While some may prefer mainstream
hits, others might favor more specialized or under-the-
radar offerings. To capture these differences, we estimate
each user’s popularity inclination using the Pareto-based
classification of items.
For each user u, we define the set of consumed items as the
items with an observed interaction (e.g., an explicit rating) in
the offline dataset. Formally,
Cu = {i | ru,i is observed }.
Since impression logs are not available in the public
benchmarks used in this study, Cu provides a behavioral
proxy for popularity inclination. The user’s popularity-
inclination ratio is then computed as
Popu = |Cu ∩ H|
|Cu| ,
where H denotes the set of popular (head) items defined in
Algorithm 1.
For example, if a user’s interaction history contains 30%
head items and 70% tail items, then Popu = 0.3. This
ratio serves as a personalized calibration signal indicating
how strongly the user’s observed behavior leans toward
popular versus tail content, and it guides the subsequent
head–tail blending during top-N construction. Importantly,
to reduce preference–exposure conflation in evaluation,
our popularity-calibration metric RMSE-PC is computed
on enjoyed items (items rated above the user’s mean),
as described in Section IV.
